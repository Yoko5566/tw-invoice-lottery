# 架構

## 分層

```
┌─────────────────────────────────────────────────────────────┐
│  入口層                                                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────────┐  │
│  │ 網頁 UI  │  │   CLI    │  │   MCP    │  │ ChatGPT     │  │
│  │ (內嵌)   │  │  twiv    │  │  stdio   │  │ Action/技能  │  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └──────┬──────┘  │
│       └─────────────┴─────────────┴───────────────┘         │
│                          engine::check_code                  │
├─────────────────────────────────────────────────────────────┤
│  核心層 invoice-core（零依賴、不碰網路與檔案）                 │
│  period │ code │ rules │ check │ cloud_index │ dataset │ json │
├─────────────────────────────────────────────────────────────┤
│  取用層                                                       │
│  invoice-scrape（官方頁面 + PDF + SHA-256）                    │
│  invoice-qr（證明聯 QR → 欄位）                                │
└─────────────────────────────────────────────────────────────┘
```

## 為什麼核心層刻意零依賴

`invoice-core` 只有 `std`。好處：

1. **可測試**：不需要 mock 網路，全部是純函式。
2. **可移植**：同一套規則可以搬去 WASM、嵌入式、手機原生層。
3. **判讀成本低**：對獎規則是有法律後果的邏輯，程式碼越少人為錯誤越少。

## 關鍵資料結構

### 期別 `Period`

```rust
struct Period { roc_year: u16, slot: u8 }   // slot 1..=6
```

- `code()` → `11504`（財政部 5 碼）
- `draw_date()` → 該期結束月的次月 25 日
- `redeem_window()` → 開獎次月 6 日起三個月
- `pdf_tag()` → `20260708`（官方 PDF 檔名前綴）

**這三者都與官方頁面文字做過交叉驗證**（`invoice-scrape::fetch_draw_page`），
一旦推算與公告不符就中止抓取，避免把錯的期限告訴使用者。

### 字軌 `InvoiceCode`

10 碼 `AB12345678` 壓成 37 bit：

```
bits 36..27  英文字軌索引 0..675（26×26）
bits 26..0   8 位數字 0..99,999,999
```

好處是雲端獎名單可以用 `u64` 排序陣列處理，不必存字串。

### 雲端獎索引 `CloudTier`

官方 500 元獎一期 **435 萬筆**，PDF **129 MB**。直譯不可能塞進輕量 App。

```
每 128 筆一塊
  anchors[i] : 該塊第一筆絕對值（u64）
  offsets[i] : 該塊在 deltas 的起始位移（u32）
  deltas     : 塊內相鄰差值（LEB128 varint）
```

- 實測：435 萬筆 → **10.02 MB**，每筆 2.42 bytes
- 查詢：二分找塊 + 塊內線性掃描 ≤128 筆
- 沒有這層，App 不可能維持「單檔 + 開程式才連網」

## 對獎流程

```
使用者輸入
   │
   ├─ 10 碼字軌 ──────────────┐
   ├─ 8 碼紙本數字 ───────────┤
   └─ 發票照片 → QR → 欄位 ───┤
                              ▼
                    resolve_period(期別)
                              │
                              ▼
              ┌───────────────┴───────────────┐
              ▼                               ▼
      check_draw（一般獎別）          CloudIndex.lookup
      特別獎/特獎/頭獎/二~六獎        雲端專屬獎四級
              └───────────────┬───────────────┘
                              ▼
                     取最高獎項（法規：擇一領取）
                              │
                              ▼
              補上稅務、期限、統編等注意事項 → JSON
```

## 安全性

| 面項 | 做法 |
|---|---|
| 服務綁定 | 只綁 `127.0.0.1`，不對外開放 |
| 上傳大小 | 上限 32 MB，超過回 413 |
| 內容型別 | `/api/scan` 只接受 `image/*` |
| 更新完整性 | 所有下載內容先驗 SHA-256 才落盤 |
| 前端 XSS | 所有輸出一律 `escapeHtml`，無 `innerHTML` 拼接使用者資料 |
| 隱私 | 不寫入日誌、不上傳第三方；照片只在記憶體中處理 |
| 依賴 | 4 個第三方 crate，無框架 |

## 擴充點

- **OCR 補救**：紙本長條發票沒有 QR 時，可在 `invoice-qr` 加入 OCR 後備。
- **多期雲端索引**：`data/` 下以 `cloud_<期別>.bin` 命名，天然支援保留歷史期。
- **其他載具**：手機條碼載具的中獎通知屬於電子發票平台業務，不在本專案範圍。
